# ADR 0004: PoC向けMVPスコープ凍結 (2026-05)

- ステータス: 採用
- 日付: 2026-05-10
- 対象: PoC納期 (2026年5月中旬) に間に合わせるためのスコープ確定
- 関連: [ADR 0001](./0001-2026-production-modernization.md), [ADR 0002](./0002-operator-console-human-handoff.md), [ADR 0005](./0005-clerk-authentication.md), [docs/mvp-scope-2026-05.md](../mvp-scope-2026-05.md)

## 背景

ADR 0001 はReact監視・RAG・Twilio Voice SDK・Conference引き継ぎまで含む大きな移行計画でした。2026年4月時点でCloud Run基盤・050番号切替・OpenAI Realtime GA対応・Firestore/Sheets通話ログ・Twilio署名検証は完了しています ([ADR 0003](./0003-call-log-firestore-sheets.md), `docs/security-privacy-logging.md`)。

ただし2026年5月中旬という顧客 (東明社等) のPoC納期と、フロントエンド側の遅れ、PoC予算 (20万円想定) を踏まえると、ADR 0001 / ADR 0002 のフルスコープでは間に合いません。

寺田主導で「既存backend資産 + 最低限のReact UI」に集約してPoCを成立させる方針が取られたため、本ADRでMVPスコープを正式に凍結します。

## 決定

PoC (2026年5月中旬) の対象を次の通りに絞ります。

### MVPで実装するもの (In-Scope)

1. Clerk認証 (無料枠) を導入し、管理画面アクセスを保護する ([ADR 0005](./0005-clerk-authentication.md))。
2. React + TypeScript の最低限の管理画面を新設する。
   - ログイン / ログアウト
   - 通話履歴一覧 (Firestore `speech-assistant-logs/callLogs` 直読み)
   - AI設定 (システムプロンプト + Markdown形式ナレッジ直書き)
3. Firestore通話ログに **再架電フラグ** を追加し、Sheetsにも列を増やす。
4. backendに認証付きREST APIを追加する (`GET/PUT /admin/config`、`GET /admin/calls`)。
5. 通話開始時にFirestore `adminConfig` から動的にSYSTEM_MESSAGEとMarkdownナレッジを読み出してOpenAI Realtimeセッションへ反映する。

### MVPでは実装しないもの (Out-of-Scope, フェーズ2以降)

| 項目 | 既存Issue | フェーズ2以降の扱い |
| --- | --- | --- |
| backend TypeScript化 | #6 | フェーズ2、ADR 0001のWave 2 |
| 通話状態のリアルタイムイベントストリーム (SSE/WS) | #11 | フェーズ2、運用ニーズ確認後 |
| Twilio Voice SDK ソフトフォン | #13 | フェーズ2、ADR 0002 |
| AIパスアップ通知のリアルタイム配信 | #15 | フェーズ2、再架電フラグで代替 |
| Twilio Conference参加者制御 | #17 | フェーズ2、ADR 0002 |
| ベクトル化RAG / チャンク化 / 検索インデックス | #14, #29 | フェーズ2、Markdown直書きで代替 |
| PDF/PowerPoint対応 | #30 | フェーズ2、Markdown直書きで代替 |
| ノードベースのコールフロー構築UI | 未起票 (フェーズ2以降) | フェーズ2、システムプロンプト1枚で代替 |
| CRM/SFA・Slack/Teams連携 | 未起票 (フェーズ2以降) | フェーズ3以降、Sheets手動運用で代替 |

## 理由

- 既存backend (Twilio + OpenAI Realtime + Firestore + Sheets) は本番稼働済みで、コア通話体験は再構築せずに済む。
- リッチRAGや人間ハンドオフはPoC検証指標 (AIが業務要件を満たすか / 折り返し要否を判定できるか) には必須でない。
- Markdown全文をシステムプロンプトに同梱する方式なら、ベクトルストアや検索インフラを新設せず納期に間に合う。
- 「再架電フラグ + 人間が後で架電」運用は、リアルタイムホットトランスファー無しでも顧客体験を損なわず、Twilio Conference / WebRTC実装を後回しにできる。
- backend のTypeScript化はPoCでは便益より移行コストが大きい。React側のみTSで書く。

## 影響

- ADR 0001 はWave 1-2A (現状実装済み) までを正式採用とし、Wave 2B以降のうち本ADRで凍結対象となった範囲はフェーズ2へ送る。
- ADR 0002 (オペレーターWebRTC・Conference引き継ぎ) はステータスを「PoC対象外、フェーズ2で再開」に改訂する。
- 既存Issue #6, #11, #13, #14, #15, #17, #29, #30 には `deferred-post-poc` ラベルを付与し、コメントでPoCで凍結する旨を明記する。
- #2, #12 はMVPサブセットへスコープを縮小する旨をコメントで残す。
- 新規Issueとして「Clerk認証導入」「React管理画面ガワ」「通話履歴一覧」「再架電フラグ」「AI設定API」「動的SYSTEM_MESSAGEロード」を起票する。

## 受け入れ条件 (PoC)

- 認証されたユーザーのみが管理画面と `/admin/*` APIにアクセスできる。
- 通話一覧画面で日時・電話番号・要約・再架電フラグが確認できる。
- システムプロンプトとMarkdownナレッジをUIから編集して保存でき、次回通話のAI応答に反映される。
- 既存の署名検証・プライバシーログ無効化・Firestore/Sheets書き込みが引き続き動作する。
- Cloud Run develop環境への自動デプロイが継続する。
