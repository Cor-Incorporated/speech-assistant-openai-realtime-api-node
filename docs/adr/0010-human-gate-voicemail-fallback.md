# ADR 0010: 人間ゲート — 担当者が今対応できるかを確認し、不可なら留守番電話へ入れる

- ステータス: 採用（ユーザーのデプロイ承認あり。人間の接続・聴感確認は別ゲート。[有効化手順](../runbooks/human-gate-activation.md)）
- 日付: 2026-11-07
- 対象: 人間対応が必要な通話の転送、不成立時のフォールバック、通知
- 関係: [ADR-0006](./0006-handoff-phase1-pstn-transfer.md) の「不応答フォールバック」を置き換える（転送・Whisperの構成は維持）

## 背景

ADR-0006では、転送が成立しなかった発信者をAI受付へ戻して折り返し受付を完了させる設計にした。運用上の要望は次のとおり。

- 人間対応が必要な電話は担当者の電話へ転送する。
- 担当者が出たら、AIが短い要約を読み上げ、**今応答できるかを担当者に判断させる**。応答できればそのまま接続する。
- 難しい場合は発信者を**留守番電話にそのまま入れる**（AI受付へ戻して聞き直さない）。
- 緊急性のない通話はAIだけで受付を終え、メールで通知する。

ADR-0006の構成は「1を押さなければ接続しない」までは満たしていたが、(1) 2または無入力のとき発信者をAIへ戻していた、(2) 読み上げは発話の連結だけでAI要約ではなかった、(3) 留守番電話が無かった。

## 決定

1. **要約**: 転送開始と並行してAI（`HANDOFF_SUMMARY_MODEL`、未指定なら `EXTRACTION_MODEL`）が担当者向けの短い要約を作る。担当者が応答した時点で未完了なら最大 `HANDOFF_SUMMARY_WAIT_MS`（既定3秒）待ち、間に合わなければ従来の簡易要約を読み上げる。応答しない・失敗しても転送は止めない。Cloud Runでは whisper webhook が別インスタンスに届き得るため、完了判定は共有の handoff context（Firestore）で行う。
2. **判断キー**: 1=今すぐ対応して接続、2=対応できない。**2・無入力・切断・不在・話中・失敗はすべて留守番電話**。接続の成立条件は従来どおり「whisperで1を明示受諾」のみ（キャリア留守電が出ても接続扱いにならない）。
3. **留守番電話**: 発信者へ録音案内（録音される旨を含む）→ `<Record>`（最大 `VOICEMAIL_MAX_SECONDS`、既定120秒、`#`で終了）。録音完了のcallbackで録音をTwilioから取得し、`TRANSCRIPTION_MODEL` で文字起こしして、**1通のメール**（文字起こし・発信者番号・AI要約・管理画面の再生リンク）を送る。文字起こしや録音取得に失敗してもメールは送る。メッセージが無かった場合も「転送不成立・留守電なし」をメールする。
4. **通知先**: `NOTIFY_EMAIL_TO/CC`。廃止済みアドレス（`k.isayama@cor-jp.com`）はコード側で常に除外し、設定に残っていても送らない。`NOTIFY_EMAIL_BLOCKLIST` で追加除外できる。
5. **録音の取り扱い**: 録音はTwilio側に保管する。管理画面の認証付き経路（`GET /api/admin/voicemails/:recordingSid?call_sid=`）でのみ再生でき、通話ごとの保存済みIDと一致しない要求は拒否する。取得URLはTwilio APIの正規形だけを許可する（SSRF防止）。録音・全文トランスクリプトはリポジトリに入れない。
6. **ロールバック**: `HANDOFF_FALLBACK_MODE=ai_reception` で従来のAI受付復帰に戻せる（whisperの文言も従来に戻る）。
7. **非緊急受付**: 非緊急の見積・開発・業務委託もAI受付とメール通知で完結する。緊急の自動転送は `shouldAutoStartUrgentHandoff`、モデルからの転送は `shouldAllowHumanHandoff` と高精度判断の許可で強制する。ゴールデン分類は同じ下位判定を検査し、実サーバーE2Eでツール経路との差異を検査する。
8. **最終状態と再送**: Media Stream終了だけでは接続成功としない。終端callbackと保存済み受付情報が揃ってから管理記録を更新する。録音のcompleted/absentで1通通知し、Firestoreの送信権とResendの固定キーで重複を抑止する。通知失敗は503、callbackには5xxの再試行を指定する。長期障害はfailed outboxを管理APIから再試行する。

## 発見・修正した不具合

- 緊急語（至急・今すぐ等）による**自動転送が実際には発信されていなかった**。呼び出し側が `session.handoff.starting = true` を先に立てたうえで `startHandoff()` を呼んでおり、`startHandoff()` 冒頭の二重発信防止が即座に return していた。E2Eテスト（Live模擬→Twilio REST）で検出。`startHandoff()` がclaimを持つ形に統一した。
- 「納得できません」（丁寧形）が苦情として検出されず、高精度対応に入らず人間転送へ流れていた。パターンを拡張。

## 影響

- 発信者は、担当者が出られない場合にAIから再度質問されなくなる。折り返し先の聞き取りは、留守電の内容と発信者番号（Twilio）で行う。
- 追加の外部費用は、要約（短い1回）と留守電の文字起こしのみ。通話あたりの増分は数円以下の見込み。
- 留守電経路では折り返しに必要な発信者番号を handoff context（Firestore `handoffs`）へ保存する。通話ログと同じ管理者のみが参照できる領域で、保持期間は通話ログの運用に従う。
- 夜間など担当者が出られない時間帯は、転送の呼び出し（`HANDOFF_DIAL_TIMEOUT_S`、既定20秒）のあと留守電になる。時間帯による転送抑止は本ADRの範囲外。
