## 再現して修正した問題

| 対象 | 修正前の観測 | 修正と回帰の範囲 |
|---|---|---|
| 管理画面の選択切替 | Aを編集中にBを選択しGETを遅延すると、BへAのメモ・状態をPATCHして200 | ID単位で詳細を再生成、古い応答を破棄。遅延中は旧保存UIなし、Bは未変更 |
| 受付運用 | 手動受付・担当者・折返し状況・抽出訂正が画面から完結しない | 既存APIに接続。画面で登録→訂正→保存→再読込と履歴を確認 |
| 留守電 | 認証付き再生URLは存在するが通話詳細から辿れない | 既存handoff記録から音声メタデータを取得し、録音・通知受付状態と再生を表示 |
| ナレッジ削除競合 | v1読取→他者がv2更新→旧If-Match DELETEが200 | serviceまでexpectedVersionを渡し412、削除の副作用なし |
| 通知の偽成功 | 外部送信0のままnotifiedAtとaudit successを記録 | 既存Outboxへ接続しprovider accepted後のみ記録。送信中202、無効503、失敗502 |
| 通知と受諾の競合 | 並行更新で受諾・接続済み状態を通知済みへ戻す危険 | CAS再読取、accepted再利用、同時要求の単一配送。ACK/接続/終端を維持 |
| 期限・ページ送り | 期限の評価なし。新500件の外にある古い未処理へ到達できない | 担当・期限入力、期限超過算出・絞込、raw走査cursor。501件・同時刻507件・cursor対象削除を検査 |
| 権限 | viewerが旧APIから更新、訂正履歴・引継ぎ要約から個人情報取得 | 既存permissionを旧新API、録音、再送へ統一。自由記述・履歴もPII投影 |
| Provider障害 | Realtime切断・429・server_error、Live session.closedで無音接続が残る | 即時終端または既存期限内の可聴復旧を待って終端し、失敗を記録 |
| ノイズと無応答監視 | 拒否されるHi.でもtool watchdog解除 | 受理した発話だけが監視を解除 |
| Twilio stop・重複接続 | stop後もproviderが開く。同一CallSidの2接続がsessionを共有 | stop終端・遅延media拒否。接続ごとのsessionとprocess内の単一所有、2本目4409 |
| WS入力サイズ | ws既定100MiBを認証前にも受理可能 | 64KiB上限。超過1009、provider生成0 |
| 入力ゲート | password/machine/rpc等をWord/Mac/PCの部分一致で受理 | 英数字境界で誤許可を抑止。PCが・Wi-Fi等は維持 |
| 営業時間 | 現在時刻・例外日を決定的に判定するtoolなし | JST週次/例外日toolをLive/Realtimeへ接続。未設定はunknown、緊急転送24時間可を維持 |

通知のacceptedは送信サービスによる受理であり、メール受信・担当者受諾ではない。
音声UIの再生は合成音で確認し、録音取得のAPI権限は実index＋stubで確認した。
Firestoreページングは実Repository＋query stubとインストール済みSDKで検査した。
この段階の結果を本番Firestoreや実電話での受入と同一視しない。

## 背後騒音の実API測定

Kyoko合成音声2発話、μ-law 8kHz、gpt-live-1 / harema / gpt-5.6-luna。
無雑音、白色雑音SNR20/10/0 dB、同音量の別話者、雑音のみ、別話者のみの計12条件。
各条件1回、最長入力10秒、クリッピング0。音声層と記録専用toolを測り、PSTN・メールは使っていない。
本番index全体の通話試験ではない。意図一致は既存分類helperと記録専用toolの結果であり、本番dispatcherの転送判断は別検査。

| 条件（各2発話） | CER：見積依頼 / 緊急依頼 | ASR番号完全一致 | tool番号完全一致 | 意図一致 |
|---|---:|---:|---:|---:|
| 無雑音 | 11.1% / 0% | 2/2 | 2/2 | 2/2 |
| 白色雑音 SNR20 | 2.8% / 0% | 1/2 | 1/2 | 2/2 |
| 白色雑音 SNR10 | 22.2% / 23.3% | 2/2 | 1/2 | 2/2 |
| 白色雑音 SNR0 | 30.6% / 80% | 0/2 | 0/2 | 1/2 |
| 別話者 SNR0 | 125% / 100% | 0/2 | 0/2 | 1/2 |

CERはNFKC・句読点除去・数字読みの正規化後の編集距離。挿入が多ければ100%を超える。
小標本なので、この表を母集団の認識率・競合優劣・p95保証として扱わない。

- SNR20でも番号が12桁へ重複する例があった。本番の電話番号helperを、見積依頼の業務受付・連絡先必須フラグを立てた条件で検査すると、too_longとして再聴取を要求し、終話を拒否した。
- SNR0で誤った11桁が得られると形式検証だけでは区別できない。復唱未確認・明示否定では終話を拒否するが、利用者の肯定に依存する。この肯定・否定はofflineの文字列注入であり、騒音下の実音声会話での救済は未検証。
- 緊急依頼が雑音で別の日本語へ変わった2条件では緊急性を検出できなかった。白色雑音では聞き直し、別話者では番号9として受け付ける応答だった。両条件とも終話tool・終端文言は観測していない。別途helperへcallback不要の終話要求を注入すると終話を許可したが、実通話で誤終話したという観測ではない。
- 白色雑音のみは転記0・tool0。別話者のみは背景の実発話を入力として受理した。
- 入力送信終了→最初の非無音出力は発話10条件（雑音のみ2条件を除外）で中央値1.612秒、最大3.139秒。相づちを含み、業務処理完了・相手の聴取時刻ではない。
- API報告290秒、全session wall合計321.033秒、最大26.818秒、APIエラー0。
- 費用推計$0.2464（請求確定値ではない）。[Live](https://developers.openai.com/api/docs/models/gpt-live-1)・[Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)の確認時料金に基づく。別途接続smokeの微少利用がある。

測定根拠はローカル `logs/cor-adversarial-20261107/noise/` のmanifest、各result、API台帳に保存。
生の合成音ファイルは一時コーパスに留め、録音・資格情報をコミットしない。

## 未達・受入の境界

1. SNR0・別話者の認識品質は未達。一字日本語姓の単独入力は、氏名収集中の文脈が無い文字列ゲートでは依然拒否される。
2. 同一CallSidの単一所有はprocess内のみ。別Cloud Run instance間の排他と複数Stream legの管理状態は未検証。
3. 個人向けSSO・複数人の認証入口、ライブ監督/介入、CRM/SMS、全保存先の保持期限・消去は追加実装が残る。
4. 期限超過の一覧化は実装したが、自動リマインドschedulerは未実装。担当者が一覧で確認する運用。
5. 営業時間の実会社設定は未投入。未設定を24時間営業とは案内しない。緊急転送はユーザー指定どおり24時間可。
6. 依存auditは本番13件（high7/moderate6）、全体17件（high11/moderate6）。このレビューでは到達性を評価し、無差別更新はしていない。
7. 人が転送を受けて1/2を押す判断、電話越しの聴感は指定時間以降の人間ゲートとして残る。
