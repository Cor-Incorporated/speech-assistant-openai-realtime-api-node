## 2. 変更の要点

- `lib/handoff-routes.js`（新規）: 転送後のwebhook（whisper / whisper-confirm / leg-status / dial-status / voicemail-complete / recording-status）と、認証付き録音再生を、依存注入のプラグインとして `index.js` から切り出した。
- `lib/handoff-summary.js`（新規）: 担当者向けAI要約。応答時に未完了なら最大3秒待ち、間に合わなければ簡易要約。
- `lib/voicemail.js`（新規）: 録音取得（Twilio正規URLのみ）、文字起こし、メール本文。
- `lib/call-disposition.js`（新規）: 「人間ゲートに入るか」の判定を本番とテストで共通化。
- `lib/twiml.js`: whisperの文言（1=今対応 / 2=対応不可→留守電）、留守電TwiML。
- `lib/handoff.js`: 設定追加（`HANDOFF_FALLBACK_MODE` ほか）、context更新を差分書き込みに変更（要約完了とwhisper状態更新の競合で上書きされないため）、「納得できません」を苦情として検出。
- `lib/notification-outbox.js`: 廃止済み宛先の除外、宛先ゼロ時はスキップ。
- デプロイワークフローと `.env.example` に新設定を追加。

## 3. 発見して修正した不具合

1. **緊急語による自動転送が実際には発信されていなかった**。呼び出し側が `starting` フラグを先に立てたうえで `startHandoff()` を呼び、`startHandoff()` 冒頭の二重発信防止が即returnしていた。既存の単体テストでは検出されず、実際の `index.js` を起動するE2Eで初めて検出した。
2. 「納得できません」（丁寧形）が苦情として扱われず、高精度対応を経ずに人間転送へ流れていた。ゴールデンテストG-P05で検出。

### シナリオテスト（`test/handoff-human-gate.test.js`）

担当者応答→1で接続／2で留守電／無入力／不在・話中・失敗・キャンセル／キャリア留守電相当、録音完了→メール（文字起こし・発信者番号・AI要約・再生リンク）、Twilio再送の重複防止、不正な録音URLの拒否、文字起こし失敗・録音取得失敗時の縮退、無言留守電の通知、AI要約の待機と簡易要約への縮退、context障害時のプロンプト、ロールバックモード、署名不正403／無効時404、管理画面の録音再生の認可。

### E2Eテスト（`test/human-gate.e2e.test.js`）

実際の `index.js` を起動し、GPT-Liveを模したWebSocketから通話を流す。Twilio REST・OpenAI HTTP・Resendはローカルスタブへ向け、Twilio署名検証は有効のまま署名付きでwebhookを呼ぶ。

1. 至急の発話 → Twilioへ転送TwiML更新（転送先、`answerOnBridge`、whisper URL）→ AI要約が読み上げられる → 1で接続 → `<Hangup>`（AIへ戻らない）
2. 至急 → 2を押す → 留守電 → 録音完了 → 文字起こし入りのメールが `to=ops` / `cc=team` のみに届く（廃止アドレスは除外）→ 管理画面の録音再生は認証必須
3. 担当者が出ない（no-answer）→ 留守電（`handoff_fallback` のAI受付へは戻らない）
4. 急ぎではない開発見積 → バックエンドが `transfer_to_human(contract)` → 同じ転送先へ
5. 営業電話 → バックエンドが転送を試みても発信されない。終話後に要約メールが届く

## 6. 調査結果（GPT-Live-1 + Twilio構成）の扱い

- 現行構成はすでに「GPT-Live-1（`LIVE_MODEL`）＋バックエンドモデル委譲（`LIVE_BACKEND_MODEL`）＋μ-law 8kHzパススルー＋Realtimeへの自動フォールバック」で、調査が推奨する構成と一致する。モデルの載せ替えは行っていない。
- 調査に記載のあった日本語ネイティブ音声（`harema` / `shida`）と Twilio Agent Connect は、この環境では実APIで確認できていない。音声は `LIVE_VOICE` で切り替えられるため、実APIキーがある環境で `scripts/verify-live.js` を使い、利用可否と聞こえ方を実測してから変更することを推奨する。
- 調査の数値（コスト・Arena順位など）は未検証の情報として扱い、本実装の判断根拠にしていない。
